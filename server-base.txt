# The fork's whole diff against upstream is eight files. Three reach this image:
#   - deploy/docker/Dockerfile: COPY integrations/, without which the slack
#     extra does not resolve at build time.
#   - integrations/slack: the paginated built-in agent/host listing the Slack

# Platform's vendored Kustomize tree MUST come from the same upstream commit. The
# launcher creates batch/v1 Jobs: its RBAC lives in that tree, its API calls live
# in this image, and a split between them 403s every managed sandbox launch while
# the server reports healthy. The platform bump that pins this digest re-syncs
# the tree to 63231a044.
#
# MIGRATIONS run at boot. This base crosses eleven revisions, ge1b2c3d4e5f ->
# ll1a2b3c4d5e. Rehearsed on postgres:16-alpine loaded with dev's schema-only
# dump and synthetic rows at dev scale (121 hosts, 7 users, 139 conversation
# metadata rows): upgrade 225 ms, downgrade 65 ms, re-upgrade 81 ms, row counts
# intact. Three revisions can discard data, and each acts only on a column that
# an earlier revision in this same chain creates, so no data that exists before
# the upgrade is lost:
#   - ll compress_inference_snapshot NULLs any snapshot over 65,535 compressed
#     bytes. Its docstring requires readers and writers stopped; the server's
#     Recreate strategy satisfies that.
#   - kk preferences_value_blob deletes preference rows over 65,535 bytes.
#   - jj move_project_order_to_preferences drops users.project_order after
#     copying it.
#

# with "Omnigent database schema is newer than this version of Omnigent", so
# reverting the digest alone crash-loops. Run `alembic downgrade ge1b2c3d4e5f`
# FROM THIS IMAGE first (65 ms rehearsed), then revert. The downgrade discards
# what the new revisions stored since the upgrade: preferences, inference
# snapshots, account-revocation markers.
