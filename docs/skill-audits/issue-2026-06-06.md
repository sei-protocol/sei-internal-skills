# Skill Audit — `issue`

**Shape:** procedural

## Summary

- **Block:**   0 (after remediation)
- **Warn:**    3 (remediated)
- **Info:**    1 (N/A)

The audit ran while extending `/issue` from GitHub-only to GitHub-or-Linear. It surfaced three pre-existing convention gaps in this canonical skill, all fixed in the same pass.

## Findings (pre-existing gaps, remediated)

### B-class — missing canonical sections (block for procedural shape)

- **No `evals/` directory** — the skill shipped with no evals at all (E1/E2). Added `evals/evals.json` with 4 evals (2 happy: GitHub + Linear; 2 halt: Linear-MCP-unavailable, fix-framing pushback).
- **No Guardrails stanza (B2)** — added a 5-condition stanza (never auto-create; never fabricate; Problem-is-behavior; create-never-update; degrade-don't-block).
- **No Halt Conditions section (B3)** — added (missing required fields; sink unavailable; fix-only framing; multiple slices).

### D-class — description (warn)

- **D1** — description didn't open with "Use when"; reworded to "Use when synthesizing…".
- **D6 (Obra CSO trap)** — description narrated the workflow ("Produces a body with … then asks whether to file to GitHub/Linear/print"); trimmed to route on WHEN, not HOW.
- **D4** — no sibling-skill redirect; added "NOT for capturing this work's design (use /design)".

## Cross-review (platform-engineer) — Linear path vs MCP contract

Verified the Linear path matches the `save_issue` MCP contract precisely: create omits `id` (passing `id` updates an existing ticket), `title` + `team` required, `description` as literal-newline Markdown, team always resolved via `list_teams` (no default, no repo-inference), optional `project`/`labels`/`priority`/`assignee` offered-not-forced. MCP-unavailable degradation is triple-covered (guardrail + halt condition + eval), forbidding fabricated identifiers/URLs. GitHub path is byte-identical to `main` — backward-compatible.

Two should-fix/nit items from the cross-review, both fixed in-pass:
- `references/example-output.md` still showed the old 2-option create prompt → updated to the 3-sink prompt.
- `coral/SKILL.md` summary line said the next-workstream pointer is a URL → generalized to "GitHub URL, or Linear identifier + URL".

## Cross-review pass (`/cross-review`, 2026-06-06)

After the audit, the change was run through `/cross-review` with three independent blinded reviewers (platform-engineer = correctness; general-purpose = standards conformance; product-manager = assigned dissent / completeness). The standards reviewer found full alignment; correctness passed; the dissenter surfaced one genuine blocker and several gaps. Resolved in-pass:

- **Lineage debt (blocker).** `linear-integration.md` claimed a closed bidirectional `/design` ↔ issue loop, but `/design --issue <n>` is GitHub-number-only and was not extended. Corrected to state the gap plainly and added an explicit **"Deferred — `/design` Linear lineage"** entry (un-defer when a Linear-tracked issue is first picked up for a design pass). Note: the `/design`-side docs (`design/SKILL.md`, `design/references/issue-integration.md`) are **intentionally left untouched** in this PR — its scope is `/issue` — so the open loop is acknowledged here rather than threaded from both sides. Closing it is the `/design` follow-on change.
- **Return-shape fabrication seam** (flagged independently by platform-engineer and the dissenter). Added: if `save_issue` returns without an identifier/URL, report the raw response — never synthesize one.
- **Named-team-not-found.** Added handling (present the real list; never fall back to a default team) as both a procedure step and a Halt Condition.
- **`--team` CLI notation** on `list_projects`/`list_issue_labels` reworded to MCP-tool phrasing (there is no Linear CLI); added "ask the user to name it" guidance for long lists.
- **Sub-issue / cross-post** explicitly deferred (one sink, one issue per invocation).
- **Cold team on handoff** documented in `coral-integration.md` and `linear-integration.md` (Linear team is always interactively resolved; no pre-filled destination promised on a handoff).

- **Already-named-sink re-prompt (#8).** Refined per follow-up: if the invocation already names a sink ("file this in Linear"), honor it without re-asking; an *unstated* sink is still always asked, and a sink is never silently inferred from context. The invariant "show the body before creating; never infer" is preserved. Guardrail #1, Procedure step 5, and the `happy-path-linear` eval updated to match.

## Nits (accepted, not changed)

- Mild "issue"/"ticket" terminology drift (B6) — "Linear ticket" is intentional user-facing vocabulary in triggers; "issue" is the artifact elsewhere. Left as-is.
- The **T2 info** (`state/.gitkeep`) does not apply: `/issue` keeps no skill-internal `state/`.
