# Implementation Plan: a sibling that is not a specification

Spec Kit puts this file beside `spec.md`. It is a plan, so the normative contract
does not apply to it.

The source may address a second endpoint. A caller should prefer the load
endpoint when the run names only one. An implementer must read the as-is before
writing the to-be.

None of those three sentences states a requirement. Each describes a design, so
uppercasing the keyword would assert something the plan does not mean.

This file carries no Semantic Anchors block, no Success Criteria, and no
Independent Test, because none of those belong in a plan.

A decision was made to keep the prose rules on.
