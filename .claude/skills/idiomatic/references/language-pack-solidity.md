# Solidity idiom pack

Written against `_TEMPLATE.md`. Cite §2 authorities in findings. Like the Go/Rust/TS packs, the value is to give findings a **citation** and to encode the **divergences** (§3) where older Solidity habits are *wrong* for modern (≥0.8) Solidity. Findings cite an authority plus, where one exists, a checkable **lint anchor** from §7.

**Idiom vs. security — read this first.** This is an *idiom* lens. Several Solidity idioms are also security-critical (reentrancy ordering, access control, checked external calls). This pack flags the **idiomatic form** of those (is CEI ordering present? is visibility explicit? is `msg.sender` used for auth? is the return value checked?) and cites the detector — but the **exploit-depth verdict is deferred to `security-specialist`**. A §7 row marked **[SEC→defer]** means: surface the idiomatic finding and the detector, then hand the severity/exploitability call to a security review. Do not present this pack as a security audit.

Sections: §1 dimensions · §2 authorities · §3 divergences · §4 anti-patterns · §5 idiom-vs-security overlay · §6 severity model · §7 lint anchors. Grounded in the Solidity Style Guide + Security Considerations + Common Patterns, OpenZeppelin Contracts, the SWC registry, Slither, and Solhint.

> **Citing a lint anchor:** cite a Slither detector / Solhint rule / solc warning **only** from §7. For Slither, **all detectors run by default** — weight a finding by its **Impact + Confidence** (in §7), don't treat every detector as equally blocking. For Solhint, cite whether the rule is in **`solhint:recommended`** (most idiom rules are `warn`; only `compiler-version`/`no-console`/`quotes` are error-level). Never assert a detector/rule name from memory. If §7 marks a dimension *judgment-only*, say so and cite the prose authority; do **not** fabricate a detector.
>
> Worked before/after pairs (loaded **on demand**): `examples-solidity.md` — each lint-anchored pair was verified by running `slither`/`solhint`/`solc`, so the §7 anchors are demonstrated, not asserted.

## 1. dimensions[]

| id | dimension | idiomatic rule | cue | authority |
|----|-----------|----------------|-----|-----------|
| S1 | Checks-Effects-Interactions & reentrancy | Update state **before** any external call; treat every external call as able to re-enter. CEI is the primary idiom; a `nonReentrant` guard is defense-in-depth, not a substitute for ordering. | a state write *after* a `.call`/transfer; reaching for `ReentrancyGuard` while leaving the state update last. | Solidity Security Considerations (CEI / Reentrancy); SWC-107; lint: `reentrancy-eth`, `reentrancy-no-eth` **[SEC→defer]** (§7) |
| S2 | External calls | Check the return of every low-level `call`/`send`/`delegatecall` (they return `false`, don't revert); prefer a typed interface call or a library over raw `.call`; **pull over push** for payouts. Never `delegatecall` an untrusted callee. | `(bool ok,) = …call(…)` with `ok` unchecked; raw `.call`/`.send`; pushing ether in a loop. | Security Considerations; Common Patterns (withdrawal); SWC-104/112/113; lint: `unchecked-lowlevel`, `unchecked-send`, `low-level-calls`, Solhint `avoid-low-level-calls`, `check-send-result`, `no-unused-vars` (§7) |
| S3 | Visibility & access control | Declare visibility explicitly on every function and state variable. Gate privileged operations behind an access modifier (`onlyOwner`/role). Authenticate with `msg.sender`, never `tx.origin`. Validate address inputs against zero. | implicit visibility; an ungated setter/withdraw/`selfdestruct`; `tx.origin ==`; an `address` arg set with no zero-check. | SWC-100/105/106/115; Common Patterns (restricting access); OpenZeppelin Ownable/AccessControl; lint: `suicidal`, `unprotected-upgrade`, `missing-zero-check`, `tx-origin` **[SEC→defer]**, Solhint `state-visibility`, `func-visibility`, `avoid-tx-origin` (§7) |
| S4 | Custom errors over require-strings | Since 0.8.4 prefer a named `error` + `revert MyError()` over a long `require("…")` string — cheaper and machine-decodable. | `require(cond, "long string")` / `revert("string")` in ≥0.8.4 code. | OpenZeppelin v5 (library-wide custom-error migration); Solidity 0.8.4 release; lint: Solhint `gas-custom-errors`, `reason-string` (§7) |
| S5 | Arithmetic | On ≥0.8.0 arithmetic reverts on overflow by default — **no SafeMath**; use an explicit `unchecked { }` block only where wrap-around is intended and proven safe. Avoid divide-before-multiply precision loss. | `using SafeMath` on ≥0.8; an `unchecked` block whose safety isn't argued; `a / b * c`. | Security Considerations (overflow); SWC-101; lint: `divide-before-multiply` (§7) |
| S6 | Token interactions | Wrap ERC-20 `transfer`/`transferFrom`/`approve` in `SafeERC20` — non-standard tokens return `false` or nothing instead of reverting. Check the return either way. | a bare `token.transfer(...)` whose return is ignored; raw `approve` race. | OpenZeppelin SafeERC20; SWC-104; lint: `unchecked-transfer`, `arbitrary-send-erc20` **[SEC→defer]** (§7) |
| S7 | State & storage | Mark never-reassigned values `constant`, set-once-in-constructor values `immutable` (clearer + cheaper than storage reads). Use `calldata` (not `memory`) for external read-only reference args. | a state var never written (→`constant`); one set only in the ctor (→`immutable`); `memory` external arg only read. | Solidity language; OpenZeppelin usage; lint: `constable-states`, `immutable-states`, Solhint `gas-calldata-parameters` (§7) |
| S8 | Events | Emit an event on every state-changing/privileged action; `index` the params consumers filter on; events are `CapWords`. | an owner/parameter change with no event; an un-indexed event param consumers filter by. | Style Guide (event names); lint: `events-access`, `events-maths` (narrow), Solhint `gas-indexed-events` (§7) |
| S9 | Pragma & SPDX | Lead each file with an SPDX identifier and a **pinned** pragma; avoid floating `^`/`>=` in deployable contracts (deterministic compiler). | `// SPDX-License-Identifier` missing; `pragma solidity ^0.8.0;` in a deployable. | SWC-102/103; lint: `solc-version`, `pragma`, Solhint `compiler-version` (error), solc SPDX warning (§7) |
| S10 | NatSpec | Document public/external functions, events, and the contract with NatSpec (`@notice`/`@param`/`@return`/`@dev`). | a public/external function or the contract with no NatSpec. | Style Guide (NatSpec); lint: Solhint `use-natspec` (presence only) (§7) |
| S11 | Comment discipline | Comments explain *why*, sit directly above the code, follow its indentation; NatSpec (`///`, `/** */`) is the sanctioned API-doc form. Remove debug cruft (`console.log`/`hardhat/console`). **No historical/changelog reasoning in code** ("we used to…", "removed because…") — that belongs in the PR/commit. **A deletion gets no tombstone**: when a function, var, or block is removed, remove it — no comment naming what was removed or why, and **no "load-bearing context for the deletion" exception** (not even a security-relevant removal); the code states only *current* intent. | `// what` restating the next line; "we used to"/"previously"/commented-out code; **a comment naming what a removed function/block was or why it was deleted (a tombstone), even when pitched as security context**; a leftover `console.log`. | Style Guide (code layout / NatSpec); lint: Solhint `no-console` (debug only — adjacent); the no-tombstone rule is **judgment-only** (§7) |
| S12 | Inheritance & overrides | Annotate overrides with `override`; order base contracts consistently (C3 linearization); don't shadow inherited state/locals; call `super` where the pattern requires. | a shadowed inherited state var; a missing `override` (solc-enforced); an interface that should be inherited but isn't. | Style Guide (function order); lint: `shadowing-state` **[SEC-adjacent]**, `shadowing-local`, `missing-inheritance`, `unimplemented-functions` (§7) |

## 2. authorities[]

- **Solidity Style Guide** — docs.soliditylang.org/en/latest/style-guide.html — naming (`CapWords` contracts/events/structs, `mixedCase` functions/vars, `UPPER_CASE` constants, `_` prefix for non-external), layout/ordering, NatSpec. Open docs (paraphrase + cite).
- **Solidity Security Considerations** — docs.soliditylang.org/en/latest/security-considerations.html — CEI, reentrancy, sending ether, `tx.origin`, overflow.
- **Solidity Common Patterns** — docs.soliditylang.org/en/latest/common-patterns.html — the withdrawal (pull-over-push) and restricting-access patterns.
- **OpenZeppelin Contracts (v5.x)** — docs.openzeppelin.com/contracts — reference implementations: Ownable/AccessControl, ReentrancyGuard, SafeERC20, the library-wide custom-error idiom. **MIT** (paraphrase patterns).
- **SWC Registry** — swcregistry.io — the weakness taxonomy; cite stable `SWC-NNN` IDs (maintenance-frozen but the canonical ID namespace).
- **Slither + Solhint + solc** — the checkable anchors (§7). Slither (github.com/crytic/slither) runs **all** detectors by default — cite by detector name + its Impact/Confidence. Solhint (github.com/protofire/solhint) — cite the rule ID + whether it's in `solhint:recommended`. solc emits its own warnings (SPDX, unused var, shadowing, unchecked return).
- **Consensys Smart Contract Best Practices** — consensys.github.io/smart-contract-best-practices — background corroboration (pull-payments, CEI, external-call caution).

## 3. divergences[] — where modern (≥0.8) Solidity rejects older habits

Do **not** flag these as problems (and don't recommend the old form).

- **Custom errors over `require`-strings** (since 0.8.4) — `revert MyError()` is cheaper and decodable. Don't recommend long require strings.
- **No SafeMath on ≥0.8.0** — checked arithmetic reverts by default; `using SafeMath` is redundant noise. Don't recommend SafeMath; do flag a deliberate `unchecked` block whose safety isn't argued.
- **`error`/`revert`/`require`, not `throw`** — `throw` was removed (0.5.0); `sha3`→`keccak256`, `var` removed. Don't bless deprecated forms (SWC-111).
- **No constructor visibility** — since 0.7.0 constructors take no visibility; `constructor() public` is a legacy smell, not something to add.
- **`calldata` over `memory`** for external read-only reference args — avoids a copy; the idiomatic default. Don't recommend `memory` there.
- **`immutable`/`constant` over plain storage** for set-once/never-changed values — don't leave them as mutable storage "for flexibility."
- **CEI over a reentrancy guard where structurally possible** — correct ordering is the design; `nonReentrant` is defense-in-depth. Don't accept "it has a guard" as a substitute for ordering, and don't recommend adding a guard *instead of* fixing the ordering.
- **`msg.sender`, never `tx.origin`, for auth** — `tx.origin` auth is a phishing vector, never idiomatic (SWC-115).
- **Pinned pragma over floating `^`** in deployables — deterministic compilation (SWC-103).

## 4. anti_patterns[]

- **State update after external call** — cue: `balances[x] -= n` *after* `x.call{value:n}("")`. Rewrite: checks-effects-interactions — update state, then call. lint: `reentrancy-eth` **[SEC→defer]** (§7).
- **Unchecked low-level call** — cue: `(bool ok,) = a.call(…)` with `ok` never checked, or a bare `a.call(…)`. Rewrite: check `ok` and revert, or use a typed interface call. lint: `unchecked-lowlevel`, Solhint `avoid-low-level-calls`/`no-unused-vars` (§7).
- **Unchecked ERC-20 transfer** — cue: `token.transfer(to, amt);` return ignored. Rewrite: `SafeERC20.safeTransfer(token, to, amt)`. lint: `unchecked-transfer` (§7).
- **`tx.origin` auth** — cue: `require(tx.origin == owner)`. Rewrite: `msg.sender`. lint: `tx-origin` **[SEC→defer]**, Solhint `avoid-tx-origin` (§7).
- **Ungated privileged function** — cue: a setter/withdraw/`selfdestruct` with no access modifier. Rewrite: an `onlyOwner`/role modifier. lint: `suicidal`/`unprotected-upgrade` **[SEC→defer]** (the right role gating the right function is **judgment-only**) (§7).
- **Missing zero-address check** — cue: an `address` stored from input with no `!= address(0)`. Rewrite: validate. lint: `missing-zero-check` (§7).
- **Implicit visibility** — cue: a function/state var with no visibility keyword. Rewrite: state it. lint: Solhint `state-visibility`/`func-visibility` (§7).
- **`require`-string where a custom error fits** — cue: `require(c, "msg")` in ≥0.8.4. Rewrite: `error Foo(); … if (!c) revert Foo();`. lint: Solhint `gas-custom-errors` (§7).
- **SafeMath on ≥0.8** — cue: `using SafeMath for uint256;`. Rewrite: delete it; arithmetic reverts by default; `unchecked {}` only where proven safe. Anchor: judgment / §3.
- **Const-able / immutable-able storage** — cue: a state var never written (→`constant`) or set only in the ctor (→`immutable`). Rewrite: mark it. lint: `constable-states`/`immutable-states` (§7).
- **Floating pragma in a deployable** — cue: `pragma solidity ^0.8.0;`. Rewrite: pin it. lint: `solc-version`, Solhint `compiler-version` (§7).
- **Changelog comment / what-comment / commented-out code** — cue: a comment narrating past states, restating the next line, or dead code left commented. Rewrite: delete it; history lives in the PR, NatSpec carries the contract, version control holds deleted code.
- **Tombstone / removal-narration comment** — cue: a comment left at a deletion site naming what was removed or why (`// removed onlyAdmin guard (PR-42): moved to the router now`). Rewrite: delete it with the removal. **Refute the "load-bearing context for a security-relevant deletion" excuse** — the rationale belongs in the PR/commit (and, if it must be enforced, a test), never in a comment the next reader mistakes for current intent. The only sanctioned residue is a comment about *current* intent (S11) — never one whose subject is the removal.

## 5. framework_overlays[]

### Idiom-vs-security boundary (the load-bearing overlay)

Not a framework — the boundary that determines how a finding is routed. It ranks above style because mis-routing a security-critical finding (treating it as a mere idiom nit, or conversely claiming a full exploit verdict this lens can't back) is the failure mode.

| id | rule | cue | consequence |
|----|------|-----|-------------|
| SEC1 | For a **[SEC→defer]** detector (the ones marked `[SEC→defer]` in §7: reentrancy `-eth`/`-no-eth`, `tx-origin`, `arbitrary-send-*`, `suicidal`, `unprotected-upgrade`, `unchecked-transfer`, `shadowing-state`): surface the **idiomatic finding** (CEI ordering, `msg.sender`, explicit gating, checked return) and **cite the detector**, then hand the exploitability/severity verdict to `security-specialist`. | a reentrancy/access/arbitrary-send detector fires. | claiming a full security verdict overstates this lens; *ignoring* it because "security is the audit's job" lets the idiomatic defect ship. Do both: flag the idiom, defer the exploit depth. |

## 6. severity_model

- **correctness / [SEC→defer]** — S1 reentrancy (state-after-call), S3 ungated privileged function / `tx-origin` auth, S2 unchecked low-level call, S6 unchecked ERC-20 transfer. These are exploitable classes: flag the idiomatic form, cite the detector (with its Slither Impact+Confidence), defer exploit depth to `security-specialist` (SEC1).
- **idiom-divergence-with-consequence** — S4 require-string-where-custom-error-fits (gas), S5 SafeMath-on-0.8 / unargued `unchecked` (gas/safety), S7 const-able/immutable-able storage & `memory`-vs-`calldata` (gas), S9 floating pragma (non-determinism), S3 missing-zero-check, S12 shadowing.
- **style** — S8 event/indexing nits, S10 NatSpec presence, S11 comment nits, naming/layout, `explicit-types`. Bundle these; never lead with them.

Profile note: this pack is **subordinate to the repo profile** (`package-profile.md`). A repo's documented convention (e.g. a fixed compiler via Foundry config, a house error library) or its slither/solhint config (which detectors/rules are actually enabled) overrides any dimension here — reconcile against the profile and the real config first.

For **Solhint**, the table notes `recommended` membership (almost all idiom rules are `warn`). **[SEC→defer]** marks a detector whose exploit verdict goes to `security-specialist` (SEC1). Where a dimension is **judgment-only**, there is no anchor — say so and cite the prose authority; never fabricate a detector. **Genuinely judgment-only — never fabricate a detector:** pull-over-push withdrawal design (S2), authorization-model correctness (S3), SafeMath-removal & unsafe-`unchecked` blocks (S5), the OZ-SafeERC20 library choice (S6), storage-packing layout (S7), event *completeness* (S8), NatSpec *quality* (S10), the **no-tombstone / what-comment / commented-out-code rule** (S11 — no Solidity linter exists), and intended `super`/override chains (S12). Cite the prose authority + SWC-ID and say plainly no checkable rule exists.

**Provenance caveats (carry these when citing — verified by running the tools):** Slither runs **all** detectors by default, so cite the detector + its **Impact+Confidence** and don't treat an `Informational`/`Optimization` detector (`low-level-calls`, `constable-states`, `immutable-states`, `pragma`, `solc-version`) as a blocking defect; the high-impact security detectors are **[SEC→defer]** (flag the idiom, hand exploit depth to `security-specialist`). Solhint: only `compiler-version`/`no-console`/`quotes` are **error**-level in `recommended` — everything else is `warn`; `not-rely-on-time`, `ordering`, `private-vars-leading-underscore`, `payable-fallback` are **off** by default (don't claim they fire). Use the Slither `--detect` names (`unchecked-lowlevel`, `missing-zero-check`, `constable-states`) — the wiki anchors sometimes differ (`unchecked-low-level-calls`, `missing-zero-address-validation`). Solhint `compiler-fixed` was folded into `compiler-version`; `use-natspec` superseded the older comment rules — don't cite the retired names.

**Tool conflicts / idiom-divergent defaults (observed — don't mis-cite):** Solhint `func-visibility` flags an **idiomatic no-visibility constructor** (correct since 0.7 — a §3 divergence) unless the config sets `ignoreConstructors: true`; if a repo's solhint flags its constructor, that's the rule's default, not a real finding. Solhint `immutable-vars-naming` wants an immutable in `SNAKE_CASE` (`ADMIN`) while Slither `naming-convention` (Informational) wants `mixedCase` (`admin`) — the two **conflict** on immutable casing; pick the repo's convention and don't cite both against the same name. Solhint `gas-indexed-events` suggests indexing event value-params (e.g. a payment `amount`) — a gas hint, not an idiom requirement (you typically index filter keys, not values).

## Language → specialist agent

Solidity maps to **`solidity-developer`** (see the TEMPLATE specialist map). For deep Solidity judgment calls beyond this pack — and for the exploit-depth verdict on any **[SEC→defer]** finding — dispatch `solidity-developer` (it can run `forge`/`slither`); for adversarial threat analysis, `security-specialist`.
