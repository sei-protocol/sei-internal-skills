# Go idiom pack

The worked reference pack, written against `_TEMPLATE.md`. Cite §2 authorities in findings. Go's whole point in this skill: the base model knows most of this — the pack's job is to give findings a **citation** (a prose authority *and*, where one exists, a machine-checkable **lint anchor** from §7) and to encode the **divergences** (§3) where generic software wisdom is *wrong* for Go.

Sections: §1 dimensions · §2 authorities · §3 divergences · §4 anti-patterns · §5 framework overlays · §6 severity model · §7 lint anchors. Grounded in Effective Go, Go Code Review Comments, the **Google Go Style Guide** (cited as **GGSG** — a 3-document corpus, Guide / Decisions / Best Practices, CC-BY-3.0; cite a finding by document + on-page heading, e.g. `GGSG: Decisions — Naming`; full list in §2), and *Learning Go* (Bodner, 2nd ed.).

Worked before/after pairs (loaded **on demand**, not every review): `examples-go.md` — most useful for the §3 divergences and the judgment-only dimensions; each lint-anchored pair was verified by running the tool, so the §7 anchors are demonstrated, not asserted.

> **Citing a lint anchor:** when a finding has a checkable rule, cite it from **§7** (e.g. cite `ST1005` from the D2 row). Cite an anchor **only** from the §7 table — never assert a check ID from memory, and respect §7's caveats (some checks are off-by-default or version-dependent). If §7 marks a dimension **or a specific sub-rule** *judgment-only*, say so and cite the prose authority; do **not** fabricate an ID.

## 1. dimensions[]

| id | dimension | idiomatic rule | cue | authority |
|----|-----------|----------------|-----|-----------|
| D1 | Naming | `MixedCaps` not `under_scores` (constants too — never `MAX_SIZE` or a C++ `kFoo`); short names for short scopes (`i`, `t`, `err`), longer names as scope grows; exported names get a doc comment starting with the name; initialisms keep uniform case (`ID`, `URL`, `RBAC`, `S3`, `HTTP`; `XMLAPI`, mixed `gRPC`→`GRPC`/`gRPC`); no `Get` prefix on accessors (name them for the noun; use `Compute`/`Fetch` when the call is expensive). Strip recoverable context from names — don't repeat the package (`widget.New` not `widget.NewWidget`), the type (`users` not `userSlice`), or params/returns; add a type suffix only to disambiguate siblings (`ParseInt`/`ParseInt64`). Constant names state meaning, not the literal. | `under_score` idents; `MAX_*`/`kFoo` consts; exported sym w/o doc comment; `Id`/`Url`/`Http`; `GetFoo()` accessor; `pkg.PkgFoo`; `numUsers`/`userSlice`; a name echoing its param/return type. | GCR: Initialisms, MixedCaps; GGSG: Decisions — Naming / Initialisms / Constant names / Getters / Repetition; lint: `ST1003` (§7) |
| D2 | Error handling | Errors are values; wrap with `%w` + context; **`%w` goes last** (`"...: %w"`) so the text mirrors the unwrap order — *except* when wrapping a package-level sentinel to categorize, where the sentinel leads (`fmt.Errorf("%w: ...: %v", ErrKind, err)`). `%w` vs `%v` is an **API decision**: `%w` when callers should `errors.Is`/`errors.As` the chain; `%v` to deliberately sever it at an RPC/storage boundary. When an outer sentinel **and** an inner cause must both survive, multi-`%w` (`fmt.Errorf("%w: %w", ErrOuter, inner)`, Go 1.20+). Don't add redundant context the inner error already carries, and never a content-free `"failed:"`/`"error:"` prefix (the non-nil error already signals failure). Error strings lowercase, no trailing punctuation; use **consistent** verbs across sibling messages and `%s` on a `Stringer` over `%v`/`%X`; `%q` for strings that may be empty/odd; never discard with `_` silently; don't log *and* return the same error. No in-band error sentinels (`-1`, `""`, `nil`-means-found) — return `(v, ok)` or `(v, error)`. | `fmt.Errorf` without `%w` when wrapping; `%w` not last (non-sentinel); `err.Error()` string-matching; `Errorf("Failed.")`; capitalized error string; `"failed to ..."` filler; mixed `%X`/`%v` for the same kind; `%v` on a `Stringer`; a `-1`/`""` "not found" return; log-then-return-err. | Effective Go: Errors; GCR: Error Strings; Go blog: 1.13 errors; GGSG: Decisions — Error strings / In-band errors, Best Practices — Adding information to errors / Placement of %w / Logging errors; lint: `ST1005`, `errcheck`, `errorlint`, `errorsas` (§7) |
| D3 | Interface placement | Accept interfaces, **return concrete types**; define the interface in the **consumer** package, sized to what it uses; prefer narrow; no speculative interface before a second implementation exists. | Interface defined next to its only implementation; wide interface where 2–3 methods are used; interface return type for its own sake. | Go Proverbs; GCR: Interfaces; GGSG: Decisions — Interfaces; lint: judgment-only (§7) |
| D4 | Zero values | Make the zero value useful; nil slices/maps are valid for read; a `nil` slice ≡ an empty slice — declare empty as `var x []T`, test with `len(s)==0` (never `s==nil`), and don't build an API that distinguishes them. Omit zero-value fields from struct literals unless their presence aids clarity. | Constructor that only sets defaults; nil-map write; `s == nil` emptiness test; undocumented "empty means X"; zero-value fields spelled out in a literal. | Effective Go: The zero value; GGSG: Decisions — Nil slices / Zero-value fields; lint: judgment-only (§7) |
| D5 | Concurrency | Never start a goroutine without knowing how it stops — bounded lifetime, **observable exit** (context, `WaitGroup`, done channel). `context.Context` is the first param, named `ctx`, never stored in a struct; create base contexts only at entrypoints (`main`/`init`); `defer cancel()`. **No custom context type** — only `context.Context` in signatures, no exceptions. Type channel params directionally (`<-chan`/`chan<-`). Unbuffered channels by default — buffer only for a known count or deliberate backpressure. Channels orchestrate, mutexes guard state; keep concurrency an implementation detail (don't expose channels in a public API). | naked `go` with no stop path; `ctx` field on a struct; a custom context type; missing `cancel()`; bidirectional channel param where one direction suffices; arbitrary buffer size "for speed"; `select{…; default:}` busy-wait; a public func returning a channel the caller must drain. | Effective Go: Concurrency; GCR: Contexts; GGSG: Decisions — Contexts / Custom contexts / Goroutine lifetimes, Best Practices — Channel direction; Learning Go ch.12/14; lint: `lostcancel`, `containedctx` (§7) |
| D6 | Package boundaries | Package name = its purpose, not its contents; lowercase, no underscores, unbroken (`tabwriter`); no `util`/`common`/`helper`/`model` grab-bags (the rename-on-import it forces *is* the smell); imports acyclic and one-way. Library packages don't register flags or read global state as an import side effect — take config via params/fields. Test doubles live in `<pkg>test`, not `test`. | `package util`/`common`/`helper`/`model`; re-export shim that pays no rent; import cycle; a library `flag.Var` at package scope. | Effective Go: Package names; GGSG: Decisions — Package names / Flags, Best Practices — Util packages; lint: `depguard` (denylist only — §7) |
| D7 | Composition | Embedding for behavior reuse; interfaces for polymorphism — not type hierarchies. A type's methods are **all** pointer or **all** value receivers — don't mix; pointer receivers when methods mutate, the type holds a sync primitive, or it's large. | Simulated inheritance; deep embedding for data-only reuse; one type with both pointer and value receivers. | Effective Go: Embedding; GGSG: Decisions — Receiver type; lint: judgment-only (§7) |
| D8 | Function shape | Return early; keep the happy path at minimal indentation (line of sight); no `else` after a returning `if` — for a value needed past the `if`, declare it before rather than `if-init … else`. Named results only when they disambiguate same-typed returns or a deferred closure assigns them — never just to enable a naked return; **naked returns only in short functions**. Keep signatures on one line (refactor, don't wrap); don't line-break a multi-clause `if` — hoist operands into named booleans. No redundant trailing `break` in a switch case; labeled break to exit an enclosing loop. Past ~5 args, switch to an option struct or variadic functional options. | `else` after a `return`; deeply nested happy path; named results that just echo types; naked return in a long func; a wrapped signature or `if` condition; trailing `break` in a `case`; a 7-positional-arg constructor. | GCR: Indent Error Flow; GGSG: Decisions — Indent error flow / Named result parameters / Function formatting / switch and break, Best Practices — Function argument lists; lint: `nakedret`, revive `indent-error-flow`/`early-return` (§7) |
| D9 | Mutability & copies | Go is call-by-value; pointers signal *mutability* — pass one only to mutate, to satisfy an interface, or for genuinely large data, not to avoid copying a small struct. Consistent value/pointer receivers per type. A value holding a `sync.Mutex` (or other lock / pointer-receiver type) must **not** be copied — use a pointer. The `range` value is a copy — index into the slice to mutate. `DeepCopy()` shared cache objects before mutating. | `*SmallStruct` param/return with no mutation; pointer "for performance" on a tiny value; mixed receiver kinds on one type; copying a struct that embeds a lock; `for _, v := range s { v.X = … }`; mutating a client-cache object without copy. | Learning Go ch.5/6; GGSG: Decisions — Copying / Pass values; controller-runtime cache semantics; lint: `copylocks`, `SA4005` (§7) |
| D11 | Generics discretion | Type params when they remove real cross-type duplication or add type-safety an interface can't; prefer an ordinary interface when *behavior* (not the concrete type) varies, and prefer plain slices/maps first. Use precise constraints (`comparable`, `cmp.Ordered`, `~int \| ~float64` unions), not `any`. Never to build a DSL. | `[T any]` used once; a generic func whose body only calls interface methods; `[T any]` then a runtime type-switch inside. | Go generics guidance; GGSG: Decisions — Generics; Learning Go ch.8; lint: judgment-only (§7) |
| D12 | Slices & maps semantics | Slices share a backing array — `append`/re-slice alias; pre-size with `make([]T, 0, n)` **only when the length is known or it's hot** (don't speculatively preallocate); hand a sub-slice to appending code via a three-index slice `s[lo:hi:max]`; `copy` for independence, `clear` to zero in place. Prefer a nil slice over `[]T{}` (unless JSON must emit `[]`). Maps: comma-ok for presence, a nil-map write panics, **never depend on iteration order** (sort keys), `map[T]struct{}` as a set. A `map[error]T` is keyed by `==` identity — it does **not** see through `%w`, so a wrapped error misses the sentinel key (use an `errors.Is` switch to classify). Strings are bytes — `range` for runes, slice on rune boundaries. | sub-slice appended-to expecting independence; `append` in a hot loop on a zero-cap slice; `make([]T, n)` then `append` (length-not-capacity bug); `if m[k] != 0` for presence; ranging a map and asserting order; `map[error]T` looked up with a possibly-wrapped error; `s[i]`/`len(s)` treated as characters. | Learning Go ch.3; GGSG: Best Practices — Size hints; lint: `SA5000` (nil-map write), `makezero`, `prealloc` (§7) |
| D13 | Declarations & shadowing | `:=` for inferred init inside funcs; `var x T` when relying on the zero value or at package scope. Watch shadowing — a `:=` in an inner block that re-declares `err` (or a named return) drops the outer assignment (distinct from *stomping* with `=`, which is fine); don't shadow a stdlib package name. Struct literals for **other packages' types must use field names** (positional is banned across package boundaries); name fields in large/table-test literals too. Discriminators: prefer `iota` for an *internal*, name-referenced code — but first ask whether sentinel *identity* already discriminates (often no field/enum is needed at all); keep a **string** when the value is an external contract (a metric label, a wire value). No mutable package-level globals. | `x := 0` / `s := ""` just for a zero value; `if v, err := f(); …` shadowing an outer `err`; a positional literal for another package's struct; iota constants written to a DB/wire/metric format; a discriminator field/enum added where sentinel identity already suffices; exported mutable globals. | Learning Go ch.2/4; GGSG: Decisions — Field names, Best Practices — Shadowing / Composite literals / Declaring variables with zero values; lint: `shadow` (off-by-default — §7), `ineffassign`, `SA4006`, `gochecknoglobals` (§7) |
| D14 | Testing | Table-driven tests with `t.Run` subtests; `t.Cleanup` for teardown (over a returned closure); `go test -race` for concurrent code; `httptest` + `testdata` golden files. **Compare with `go-cmp` (`cmp.Equal`/`cmp.Diff`), never `reflect.DeepEqual`; don't adopt an assertion library** (testify-style) — write `if got != want` directly. Failure messages identify the function and input and print **got before want** (`Parse(%q) = %v, want %v`). Default to `t.Error` (keep going); reserve `t.Fatal` for when later assertions are meaningless — and **never call `t.Fatal` from a spawned goroutine** (use `t.Error`). Helpers take `testing.TB` first and call `t.Helper()`. Don't assert on unstable serialized output. Test the public API through real transports; don't design around mocks. Benchmarks (`Benchmark*`) and fuzz targets (`FuzzXxx`) where they earn it. | copy-pasted near-identical test funcs; `assert.Equal`/testify; `reflect.DeepEqual` with opaque failures; want-before-got; `t.Fatal` in a goroutine or for a recoverable check; a helper without `t.Helper()`; a mock for every collaborator; asserting on `json.Marshal` byte output. | Learning Go ch.15; GCR; GGSG: Decisions — Assertion libraries / Equality comparison and diffs / Useful test failures / Keep going, Best Practices — Error handling in test helpers; lint: `thelper`, `tparallel`, `SA3000`–`SA3001` (§7) |
| D15 | Imports | Imports form ordered, blank-line-separated groups: (1) stdlib, (2) project/third-party, (3) (generated) protobuf, (4) side-effect `_` imports. **Dot imports (`import .`) are banned.** Blank imports (`import _`) only in `main`/tests (plus `//go:embed`). Don't rename imports by default — rename only to resolve a collision (prefer renaming the more-local import; alias a package that collides with a common local var as `urlpkg`), and always drop underscores from generated protobuf packages with a `pb` suffix; use the same alias everywhere. | a `.`-import; a `_`-import in library code; an import aliased for no collision reason; the same package aliased differently across files; ungrouped/unsorted import block. | GGSG: Decisions — Imports / Import renaming / Import grouping / Import "dot" / Import "blank", Best Practices — Import ordering; lint: `goimports`/`gci` (grouping), `depguard` (§7) |

## 3. divergences[] — where Go rejects general software wisdom

This is the load-bearing section. Do **not** flag these.

- **Three similar lines beat a premature helper.** DRY/SRP pushes extraction at the second repeat; Go prefers a little duplication over a wrong abstraction. → Don't recommend a helper for 2–3 line repeats unless they're a correctness coupling (must-change-together).
- **Accept interfaces, return structs.** Inverts "program to an interface everywhere." Returning concrete types preserves caller optionality. → Don't recommend an interface return type for its own sake.
- **Errors are values, not exceptions.** No try/catch control flow, no panic-as-control-flow. → Clean Code's "prefer exceptions to return codes" is wrong for Go.
- **Small interfaces, defined late.** Define the interface at the consumer when a second implementation appears — not up-front with the implementation. → Don't recommend extracting an interface before there's a second caller.
- **No getters/setters.** Go drops the `Get` prefix and exposes fields. → Don't flag a public field for lacking accessors; don't recommend `GetFoo()`.
- **A little copying beats a little dependency.** → Don't recommend importing a package to dedupe a tiny helper.
- **A presentation concern belongs to its own layer, not the domain type.** General OO says give a type the data its collaborators want; for a *presentation* concern (a metric label, a log key, a display string) the inverse holds — it is the metric/log subsystem's job to map an error to a string, not the error type's job to carry it. → A typed error carrying genuine *domain* data (`ErrEvidenceOverflow{Max, Got}`, recovered via `errors.As`) is correct: **don't** flag it as "an error shouldn't carry fields." The smell is the inverse (a field whose *only* reader is observability — §4). And sentinel *identity* already discriminates errors: **don't** recommend adding a discriminator field/enum "to tell the sentinels apart."

## 4. anti_patterns[]

- **Sentinel-by-string** — cue: comparing `err.Error()` substrings. Rewrite: typed/sentinel error + `errors.Is`/`As`. lint: `errorlint` (§7).
- **In-band error sentinel** — cue: signalling failure with a magic value (`-1`, `""`, `nil`-means-found) instead of a second return. Rewrite: return `(value, ok bool)` or `(value, error)`. Basis: GGSG: Decisions — In-band errors.
- **Log-and-return the same error** — cue: `log.Error(err)` immediately followed by `return err` (or a wrap of it). Rewrite: do one or the other — let the caller decide to log; logging at every level is logspam. Basis: GGSG: Best Practices — Logging errors.
- **Observability field on a domain type** — cue: a field on an error/domain type whose only reader is a metric label, log key, or display string (often marked "stable external contract"); the domain type then has to change whenever the metric taxonomy does. Rewrite: drop the field; map the sentinel → its string at the metric/log boundary with an `errors.Is` switch — which also sees through `%w`, unlike a `map[error]T` whose `==` key silently misses a wrapped error. Keep genuine domain-data fields and recover them via `errors.As`.
- **Bespoke error API / reinvented stdlib** — cue: `err.With(fmt, args)`, `err.Label()`, a hand-rolled `Is`/`Unwrap`, or a discriminator field/enum bolted onto sentinel errors — all re-implementing `fmt.Errorf`/`errors.Is`/`errors.As`. Rewrite: plain sentinel errors + `fmt.Errorf("...: %w", ErrX)`; match with `errors.Is`, recover typed causes with `errors.As`. Ask "why a discriminator at all when the sentinels already differ?"
- **Context in a struct** — cue: a `ctx context.Context` field. Rewrite: pass `ctx` as the first arg of each method. lint: `containedctx` (§7).
- **Custom context type** — cue: a type other than `context.Context` used as a context in a signature. Rewrite: use `context.Context`; carry request values via `context.WithValue` or explicit params. Basis: GGSG: Decisions — Custom contexts (no exceptions).
- **Grab-bag package** — cue: `package util`/`common`/`helpers`/`model`. Rewrite: move each symbol to a purpose-named package.
- **Naked goroutine** — cue: `go f()` with no cancel/join. Rewrite: bound it to a context and make exit observable.
- **`else`-after-`return`** — cue: an `else` block whose `if` already returned. Rewrite: drop the `else`, dedent the happy path. lint: revive `indent-error-flow`/`early-return` (§7).
- **Trailing `break` in a switch case** — cue: a `break` as the last statement of a `case` (Go auto-breaks). Rewrite: delete it; use a labeled break only to exit an enclosing `for`. Basis: GGSG: Decisions — switch and break.
- **Mixed receivers** — cue: one type with both pointer and value receiver methods. Rewrite: make them all one kind (pointer if any method mutates / the type holds a lock / it's large). Basis: GGSG: Decisions — Receiver type.
- **Copy of a lock** — cue: passing/ranging/assigning a value that embeds a `sync.Mutex`/`sync.WaitGroup`. Rewrite: hold and pass it by pointer. lint: `copylocks` (§7).
- **Stutter** — cue: `task.TaskExecution`. Rewrite: `task.Execution`.
- **Commented-out code** — cue: blocks of code left commented out. Rewrite: delete; version control already has it. lint: gocritic `commentedOutCode` (§7).
- **Slice aliasing** — cue: a sub-slice handed off and appended to, expecting independence (or `append` mutating a shared backing array). Rewrite: `copy` to an independent slice, or cap with a three-index slice `s[lo:hi:max]`. lint: `makezero` (the `make([]T,n)`-then-append variant — §7).
- **Map-order dependence** — cue: ranging a map and relying on output order. Rewrite: collect keys, `sort` them, range the sorted keys.
- **Shadowed `err`** — cue: a `:=` in an inner block re-declaring `err`, so the outer error is never set. Rewrite: declare the vars once and assign with `=`, or check/return inside the block. lint: `shadow` (off-by-default — §7).
- **Goroutine leak** — cue: `go f()` with no termination path; a goroutine blocked forever on a channel nobody closes. Rewrite: bound it to a `context`/done channel with an observable exit.
- **`defer` in a loop** — cue: `defer x.Close()` inside a `for` (fires only at function return). Rewrite: extract the body into a function so the defer fires per iteration, or close explicitly. lint: `SA9001` (§7).
- **Typed-nil through interface** — cue: returning a concrete nil pointer as an `error`/interface, so a `!= nil` check is unexpectedly true. Rewrite: return a literal `nil` interface, or check the concrete value before returning. lint: `nilness`/`SA4023` (partial — §7).
- **Assertion library / `reflect.DeepEqual`** — cue: testify-style `assert.Equal`, or `reflect.DeepEqual` in a test comparison. Rewrite: `if got != want` for scalars; `cmp.Equal`/`cmp.Diff` (with `protocmp.Transform` for protos) for structured data. Basis: GGSG: Decisions — Assertion libraries / Equality comparison and diffs.

## 5. framework_overlays[]

### controller-runtime

These add to D1–D15 and carry runtime consequences, so they rank above style.

| id | rule | cue | consequence |
|----|------|-----|-------------|
| CR1 | Reconcile is idempotent & level-triggered — converge from any observed state. | branching on "did X just happen" vs "what is the current state". | edge-trigger assumptions drop work on missed events. |
| CR2 | No `panic`/`log.Fatal`/`os.Exit` below `main` in controller code — return errors, let the queue retry. | any `panic` in reconcile/task code. | crashes the manager instead of retrying. |

## 6. severity_model

- **correctness** — CR3, CR4 (stale-write/clobber); D9 (cache mutation, shared-slice aliasing, copy-of-lock); D12 nil-map write / `make([]T,n)`-then-append; D13 shadowed `err` (a silently dropped error); a `map[error]T` keyed lookup on a `%w`-wrapped error (silently wrong / zero value); typed-nil-through-interface; D2 in-band error sentinel.
- **idiom-divergence-with-consequence** — CR1, CR2, CR5, CR6, CR7, CR8; D2 when an unwrapped error (or `%v` where `%w` was meant) loses the chain, and log-and-return; the observability-field-on-a-domain-type and bespoke-error-API smells (they couple the domain type to a concern that owns its own layer, so the domain churns when the metric/error taxonomy does); D5 goroutine leaks / busy-wait / buffer misuse / custom-context that can deadlock or break propagation; D12 map-order dependence (flaky output); D14 assertion-library/`reflect.DeepEqual` (opaque, under-reporting test failures).
- **style** — D1, D3, D4, D7, D8, D11, D15, D14 message-format nits, the slice-presizing / nil-slice / `:=`-vs-`var` nits, error-string verb consistency, and the §4 anti-patterns without a runtime consequence. Bundle these; never lead with them.

## 7. lint_anchors[]

The machine-checkable rules behind the dimensions. **Cite an anchor only from this table** — never assert a check ID from memory (a wrong, falsifiable ID is worse than none). Honor the caveats: a check marked *off-by-default* fails the build only if the repo enabled it; *version-dependent* names must match the repo's linter version.
