# TypeScript idiom pack

Written against `_TEMPLATE.md`. Cite §2 authorities in findings. Like the Go and Rust packs, the value is less "teach TS" than to give findings a **citation** and to encode the **divergences** (§3) where general/other-language habits are *wrong* for TypeScript. Findings cite an authority plus, where one exists, a checkable **lint anchor** from §7.

Sections: §1 dimensions · §2 authorities · §3 divergences · §4 anti-patterns · §5 framework overlays · §6 severity model · §7 lint anchors. Grounded in the TypeScript Handbook, the Google TypeScript Style Guide, typescript-eslint, and the `tsc` strict family.

> **Citing a lint anchor:** cite an `eslint`/`@typescript-eslint`/`tsc` anchor **only** from §7, and carry §7's two-part caveat: (a) which **preset** the rule lives in (`recommended` / `recommended-type-checked` / `strict` / `stylistic` / off), and (b) whether it **requires type information** (`parserOptions.project`/`projectService`). **A type-checked rule silently does not run if the project hasn't wired typed linting** — so it fails a build only when both the preset is enabled *and* type info is configured. Never assert a rule name or its preset from memory. If §7 marks a dimension *judgment-only*, say so and cite the prose authority; do **not** fabricate a rule.
>
> Worked before/after pairs (loaded **on demand**): `examples-typescript.md` — each lint-anchored pair was verified by running `eslint`/`tsc`, so the §7 anchors, presets, and type-info status are demonstrated, not asserted.

## 1. dimensions[]

| id | dimension | idiomatic rule | cue | authority |
|----|-----------|----------------|-----|-----------|
| T1 | Types & assertions | Prefer inference; annotate where it documents or localizes errors. `unknown` over `any` (`any` switches off checking and propagates). Avoid the non-null assertion `!` and `as` casts — narrow with a real guard; route a forced cast through `unknown`. Use lowercase primitives (`string`/`number`/`boolean`), never wrapper types (`String`/`Number`/`Object`/`{}`). `as const` to keep literal types. | `: any` / `as any`; `x!`; `as Foo` on an unvalidated value; `: String`/`: Object`/`: {}`; a widened literal that needed `as const`. | TS Handbook: Everyday Types; Do's & Don'ts; Google TS: Type system; lint: `no-explicit-any`, `no-non-null-assertion`, `no-unnecessary-type-assertion`, `prefer-as-const` (§7) |
| T2 | Null / undefined safety | Run with `strictNullChecks` (the `strict` family) so `null`/`undefined` must be narrowed before use. Pick one of `null`/`undefined` per context; prefer an optional field `?` over a `\| undefined` union; keep `\| null`/`\| undefined` out of type aliases. Use `?.` / `??` over hand-rolled guards. | a possibly-nullish value used without narrowing; `x \|\| default` where `??` is meant; `null` and `undefined` both modeled for one concept. | TS Handbook: `strictNullChecks`, Narrowing; Google TS: Nullability; lint: `no-unnecessary-condition`, `prefer-nullish-coalescing`, `prefer-optional-chain`; tsc `strictNullChecks` (§7) |
| T3 | Discriminated unions & exhaustiveness | Model variants as a discriminated (tagged) union — a shared literal `kind` field lets the compiler narrow each branch. Prove exhaustiveness by assigning the residual to `never` (`const _: never = x`) so a new variant fails to compile. Prefer unions / `as const` objects over `enum`. | a struct-of-`Option`-flags with implicit rules; a `switch` over a union with no `never` default; an `enum` where a string-literal union fits. | TS Handbook: Discriminated unions, The `never` type, Exhaustiveness checking; lint: `switch-exhaustiveness-check`; tsc `noImplicitReturns`, `noFallthroughCasesInSwitch` (§7) |
| T4 | Async / Promises | Never leave a promise floating — `await`, `return`, `.catch()`, or explicit `void` every promise-valued statement. Don't pass a promise where a void/boolean is expected (an `async` callback to `forEach`, a promise in an `if`). | `arr.forEach(async …)`; `doAsync();` as a bare statement; `if (promise)`; an unhandled `.then()`. | TS Handbook; typescript-eslint async docs; lint: `no-floating-promises`, `no-misused-promises`, `await-thenable`, `return-await` (all **type-info** — §7) |
| T5 | Functions & API surface | Don't annotate inferable internals; **do** type the *exported* boundary (args + return). No `any` in public signatures — `unknown` + narrow. Order overloads most-specific first; collapse trailing-optional and single-arg-type-difference overloads. Callback params required, not optional, just because callers may ignore them; a callback whose result is unused returns `void`. | `any` in an exported signature; an untyped public function; general overload before specific; `any` callback return type. | Do's & Don'ts: Function Overloads, Callbacks; Google TS; lint: `no-unsafe-*` family, `explicit-module-boundary-types` (off) (§7) |
| T6 | Immutability & data | `const` by default; `let` only when reassigned; never `var`. Mark fields never reassigned `readonly`; prefer `readonly T[]` for arrays a function doesn't mutate. Preserve literals with `as const`. | `let` never reassigned; a class field set once but mutable; a param array mutated in place. | Google TS: `readonly`, `const`/`let`; TS Handbook: Literal Inference; lint: `prefer-readonly` (type-info), `prefer-const` (off) (§7) |
| T7 | Modules & exports | ES modules (`import`/`export`); never `namespace`. **Named exports only** — no default exports (keeps import names uniform and refactor-safe). `import type` for type-only imports. | a `default export`; a `namespace`; a value-import used only as a type. | Google TS: Imports/Exports, Namespaces vs Modules; lint: `consistent-type-imports` (off) (§7) |
| T8 | Naming | `UpperCamelCase` types/classes/interfaces/enums; `lowerCamelCase` values/functions/properties; `CONSTANT_CASE` module-level consts & enum members. No Hungarian/decorative affixes — no `IFoo` interface prefix, no leading/trailing `_`, no `opt_`. | `IFoo`; `_private`; `opt_x`; a `snake_case` value. | Google TS: Identifiers, Naming style; lint: `naming-convention` (off, type-info, policy-configurable) (§7) |
| T9 | Comment discipline | Comments are an **uncommon exception** — names and types carry intent. The sanctioned "above the code" docs are `/** JSDoc */` on the public API (Markdown body); `//` for implementation notes. A deliberately empty `catch` carries a comment saying why. **No historical/changelog reasoning in code** ("we used to…", "removed because…") — that belongs in the PR/commit. **A deletion gets no tombstone**: when an export, field, or block is removed, remove it — no comment naming what was removed or why, and **no "load-bearing context for the deletion" exception** (not even a security-relevant removal); the code states only *current* intent. | `// what` restating the next line; "we used to"/"previously"/commented-out code; **a comment naming what a removed export/block was or why it was deleted (a tombstone), even when pitched as security context**; a comment a rename would delete; `@ts-ignore` with no explanation. | Google TS: Comments & documentation; TS Handbook; lint: `ban-ts-comment` (adjacent); the no-tombstone rule is **judgment-only** (§7) |
| T10 | Error handling | Only `throw` `Error` instances (or subclasses) — never strings/objects. Treat a caught value as `unknown` (`useUnknownInCatchVariables`, in `strict`) and narrow before use. Model a meaningful error type, not a bare `string`. | `throw 'msg'` / `throw {code}`; `catch (e)` using `e` as `any`; control flow on string error messages. | Google TS: throw Error not strings, Catching errors; lint: `only-throw-error` (type-info); tsc `useUnknownInCatchVariables` (§7) |
| T11 | Testing | Black-box tests against the public module surface; no unused test scaffolding. Framework discipline (no focused/disabled tests, valid assertions) lives in the test plugin (`eslint-plugin-jest`/`vitest`), an opt-in dependency. | a test reaching into non-exported internals; a committed `it.only`/`describe.skip`; unused setup. | typescript-eslint; (framework rules: separate plugins); lint: `no-unused-vars` (§7) |

## 3. divergences[] — where TS rejects general / other-language wisdom

Do **not** flag these.

- **Structural, not nominal, typing.** Compatibility is by shape, not declared name — don't expect a class/brand to gate assignability without an explicit brand. Don't recommend nominal-style wrappers as if the name enforced anything.
- **Don't reach for classes / inheritance by default.** Plain object types, unions, and functions are the default unit; classes are for genuine identity/encapsulation. Don't recommend an OOP hierarchy.
- **`enum` is not the default for a fixed set.** String-literal unions or `as const` objects are erasable and structurally checkable; `const enum` is disallowed. Don't recommend an `enum` reflexively, and don't flag a union-of-literals as "should be an enum."
- **Don't annotate what's inferable.** Redundant annotations on locals/returns are noise that drifts. Don't recommend adding a type the compiler already infers (except to document an exported boundary).
- **`namespace` is legacy for module code.** Use ES modules. Don't recommend `namespace` for organization.
- **`unknown`, not `any`, is the escape hatch.** Don't bless `any` as "I'll type it later"; don't *suggest* `any` to silence an error.
- **Named exports over default exports.** Don't recommend a default export for "the main thing"; uniform named imports are the idiom (Google TS).
- **`===`/`!==`, with one sanctioned `== null`.** The lone idiomatic loose-equality is `== null` (catches both `null` and `undefined`). Don't flag `== null`; do prefer `===` elsewhere.

## 4. anti_patterns[]

- **`any` as a boundary type** — cue: `path: any`, `JSON.parse(x) as Config`. Rewrite: `unknown` + a validating narrow (schema or type guard). lint: `no-explicit-any` (§7).
- **Non-null assertion to dodge a check** — cue: `x!.foo`. Rewrite: narrow with a guard that proves non-null. lint: `no-non-null-assertion` (§7).
- **Unsound `as` cast** — cue: `as Config` on an unvalidated value (the assertion lies; no lint catches unsoundness). Rewrite: validate then narrow. Anchor: judgment (only `no-unnecessary-type-assertion` catches *redundant* casts) (§7).
- **Floating promise** — cue: a promise-valued statement not awaited/returned/handled/`void`-ed. Rewrite: `await`/`return`/`.catch()`/`void`. lint: `no-floating-promises` (type-info) (§7).
- **`async` callback to a void-callback API** — cue: `arr.forEach(async …)`. Rewrite: `for…of` with `await`, or `await Promise.all(arr.map(async …))`. lint: `no-misused-promises` (type-info) (§7).
- **Non-exhaustive switch over a union** — cue: a `switch` on a tagged union missing cases, no `never` default. Rewrite: handle every variant + `default: { const _: never = x; … }`. lint: `switch-exhaustiveness-check` (type-info); tsc `noImplicitReturns` (§7).
- **`throw` a non-Error** — cue: `throw 'msg'` / `throw {code}`. Rewrite: `throw new Error(...)` / a subclass. lint: `only-throw-error` (type-info) (§7).
- **`enum` where a union fits** — cue: a small fixed set as an `enum`. Rewrite: a string-literal union or `as const` object. Anchor: judgment (§3 divergence).
- **Default export** — cue: `export default`. Rewrite: a named export. lint: `consistent-type-imports` is unrelated; default-export is judgment / `eslint-plugin-import` (§7).
- **`namespace` for organization** — cue: `namespace Foo {}`. Rewrite: ES modules. Anchor: judgment.
- **Changelog comment / what-comment / commented-out code** — cue: a comment narrating past states, restating the next line, or dead code left commented. Rewrite: delete it; history lives in the PR, names carry intent, version control holds deleted code.
- **Tombstone / removal-narration comment** — cue: a comment left at a deletion site naming what was removed or why (`// removed retryCount (TICKET-42): the backoff struct handles it now`). Rewrite: delete it with the removal. **Refute the "load-bearing context for a security-relevant deletion" excuse** — the rationale belongs in the PR/commit (and, if it must be enforced, a test), never in a comment the next reader mistakes for current intent. The only sanctioned residue is a comment about *current* intent that stands on its own (T9) — never one whose subject is the removal.

## 5. framework_overlays[]

### Typed-linting precondition (applies to all type-info rules)

Not a framework so much as a config gate, but it ranks above style because it determines whether half this pack's anchors run at all.

| id | rule | cue | consequence |
|----|------|-----|-------------|
| TC1 | The type-checked rules (all of T4, plus `no-unnecessary-condition`, `only-throw-error`, the `no-unsafe-*` family, `switch-exhaustiveness-check`, `prefer-readonly`, `naming-convention`) require `parserOptions.project`/`projectService`. | an eslint config using `recommended`/`strict` but **not** the `-type-checked` variant, or no `project` wired. | those rules **silently do not run** — a real defect (a floating promise, a non-Error throw) ships unflagged. If typed linting is absent, those dimensions fall back to **judgment-only**; say so. |

## 6. severity_model

- **correctness** — T4 floating/misused promise (unhandled rejection, lost ordering); T3 non-exhaustive switch that returns `undefined` (tsc `TS2366`); T10 `throw` non-Error (breaks `instanceof` handling) and untyped `catch` use; T1 `any` at a boundary / unsound `as` (defeats checking downstream).
- **idiom-divergence-with-consequence** — T1 non-null `!` (suppresses an unproven invariant); T2 missing nullish narrowing; T5 `any` in a public signature; T6 mutable-where-readonly; the type-checked-linting-absent gap (TC1).
- **style** — T7 default-export / import-type, T8 naming, T9 comment nits, T11, `prefer-const`/`as const`/`??`-vs-`||` presentation. Bundle these; never lead with them.

Profile note: this pack is **subordinate to the repo profile** (`package-profile.md`). A repo's documented convention (e.g. "we allow default exports for pages") or its eslint/tsconfig (which rules are actually enabled) overrides any dimension here — reconcile against the profile and the real config first.

## 7. lint_anchors[]

The machine-checkable rules behind the dimensions. **Cite a rule only from this table** — never assert a name or preset from memory. Two facts decide whether a finding fails a build: the **preset** the rule is in, and whether it **requires type information** (`parserOptions.project`). **A type-checked rule silently does not run without typed linting** (TC1) — confirmed by running the tools: under plain `recommended` (no `project`), `no-floating-promises`/`no-misused-promises` do not fire; only `no-explicit-any` does. Where a dimension is **judgment-only**, there is no checkable rule — say so and cite the prose authority. Verified against **eslint 10.5 / typescript-eslint 8.x / tsc 6.0.3** (see `examples-typescript.md`).

**Genuinely judgment-only — never fabricate a rule:** the `type`-vs-`interface` choice (T1), discriminated-union *design* (T3), `explicit` API-boundary typing when the rule's off (T5), readonly-array preference (T6), default-export dogma & module-surface taste (T7), naming taste beyond casing (T8), the **no-tombstone / what-comment rule** (T9 — pack-carried, no lint exists), and Error-taxonomy design (T10). Cite the prose authority and say plainly no checkable rule exists.

**Provenance caveats (carry these when citing — verified by running the tools):** the modern `eslint:recommended` (`@eslint/js`) is a *small* bug-catching set — most suggestion/stylistic rules (`prefer-const`, `eqeqeq`, `require-await`) are **off by default**; the entire type-checked rule family (T4, `no-unnecessary-condition`, `only-throw-error`, `no-unsafe-*`, `switch-exhaustiveness-check`, `prefer-readonly`, `naming-convention`) **requires `parserOptions.project` and silently does not run without it** (TC1); `only-throw-error` is the current name (was `no-throw-literal`) and core `no-return-await` is deprecated in favor of `@typescript-eslint/return-await`; tsc `noImplicitReturns`/`noFallthroughCasesInSwitch` are **separate flags not implied by `strict`**; `switch-exhaustiveness-check`, `explicit-module-boundary-types`, `consistent-type-imports`, `naming-convention` are in **no preset** (opt-in). Default-on and safe to cite as build-failing *only if* the matching preset is enabled (and type info present for the type-checked ones).

## Language → specialist agent

There is no `typescript-specialist` agent in the roster today. For deep TS judgment calls beyond this pack, review on the pack + first principles and flag the gap; if TS work becomes common, a `typescript-specialist` is the un-defer.
