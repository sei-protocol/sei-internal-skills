# Sources — the platform canon

The external best-practice this skill cites. **Cite-and-link**; never reproduce reserved text. Verified against the primary source during authoring. These are the **generic floor**; the Sei profile (`sei-platform-profile.md`) is what *actually applies* and **overrides** some of these as the fleet *default* (Pod-Identity over IRSA, SOPS over CSI) — each override is flagged below. An override sets the default, not an absolute: the profile documents the narrow exceptions (IRSA for old-SDK workloads; a workload reading Secrets Manager at runtime) where the generic pattern is still in use.

- **§opengitops — GitOps principles.** Declarative; versioned + immutable in git; pulled automatically by agents; continuously reconciled (drift-corrected). The four OpenGitOps v1.0 principles (CNCF). — https://opengitops.dev/ (Apache-2.0). Implementation (Flux/Argo) is a secondary reinforcer.

- **§kustomize — base/overlay model.** "A *base* is a kustomization referred to by some other kustomization"; "An *overlay* is a kustomization that depends on another"; a *variant* = an overlay applied to a base. — https://kubectl.docs.kubernetes.io/references/kustomize/glossary/ + https://kubernetes.io/docs/tasks/manage-kubernetes-objects/kustomization/ (CC-BY-4.0). (This fleet uses the two-layer `clusters/base`+`manifests/base` form with `patches`/`components`/`replacements`, **not** `postBuild.substitute` — profile §2.)

- **§irsa — IAM Roles for Service Accounts (the generic the profile OVERRIDES).** A SA is bound to an IAM role; the pod gets a projected OIDC token exchanged via STS `AssumeRoleWithWebIdentity`; least-privilege per-SA. "You can scope IAM permissions to a service account, and only Pods that use that service account have access." — https://docs.aws.amazon.com/eks/latest/userguide/iam-roles-for-service-accounts.html (AWS docs). **Override:** the Sei fleet *defaults* to **EKS Pod Identity** (the `eks-pod-identity-agent` + per-(cluster,ns,SA) associations) — profile §3, `kit-cloud-auth-pod-identity`. IRSA is the broadly-applicable pattern + the cited mechanism; here it is **retained as the documented escape hatch** for old-SDK workloads that can't consume the Pod-Identity endpoint (prod `pacific-1` CronJobs), not banned.

- **§pod-security — Pod Security Standards + Admission.** Three cumulative levels — Privileged → Baseline → Restricted ("Heavily restricted policy, following current Pod hardening best practices") — enforced per-namespace by the built-in Pod Security Admission controller via labels. — https://kubernetes.io/docs/concepts/security/pod-security-standards/ + .../pod-security-admission/ (CC-BY-4.0). (The fleet pins `restricted` at the cluster minor + adds a CEL ValidatingAdmissionPolicy for what PSS misses — profile §5.)

- **§secrets — Secrets Store CSI Driver + SecretProviderClass (the generic the profile OVERRIDES).** Mount external-store secrets into the pod filesystem via a namespaced `SecretProviderClass`, instead of relying on plain k8s Secrets. — https://secrets-store-csi-driver.sigs.k8s.io/ + https://github.com/aws/secrets-store-csi-driver-provider-aws (Apache-2.0 / AWS). **Override:** the Sei fleet *delivers* k8s Secrets via **SOPS-in-git + per-cell KMS** (no CSI/SecretProviderClass, no ESO, no Sealed Secrets) — profile §4, `kit-secrets-sops-kms`. This overrides the *delivery* path only: a workload may still read a secret from AWS Secrets Manager at runtime via its own role (`heatseeker`), so SM is not fleet-absent — what's absent is SM/CSI as the k8s-Secret delivery mechanism. *(Caveat: the "plain k8s Secrets are only base64-encoded at rest by default" rationale is widely repeated and corroborated via the k8s docs index, but was not re-quoted from the encryption-at-rest page during research — treat it as corroborated-not-primary; verify that page before citing it as a load-bearing fact.)*

- **§nsa-cisa — Kubernetes Hardening Guide.** Run containers non-root; read-only root filesystem ("Use read-only root file systems where possible"); minimal base images ("Use minimal base images to reduce attack surface"); RBAC least-privilege. NSA/CISA Kubernetes Hardening Guidance v1.2 (Aug 2022) — **US Government work, public domain** (most citation-friendly of the set). **Cite the k8s.io blog summary as the verified source** — https://kubernetes.io/blog/2021/10/05/nsa-cisa-kubernetes-hardening-guidance/ (CC-BY-4.0); the canonical PDF is https://media.defense.gov/2022/Aug/29/2003066362/-1/-1/0/CTR_KUBERNETES_HARDENING_GUIDANCE_1.2_20220829.PDF. *(Caveat: the .mil PDF 403'd the research fetcher and its page/section numbers were never verified — do **not** pin a specific page or section; cite the substance via the k8s.io blog, and quote the PDF directly only after you've opened it.)*

**Lint / tooling anchors (confirmed):** kubeconform (manifest schema vs OpenAPI/CRDs), conftest/OPA (Rego policy over manifests + IaC), checkov (Terraform + K8s misconfig vs CIS), kube-score (runAsNonRoot/readOnlyRootFilesystem/limits/probes/NetworkPolicy), Pod Security Admission (runtime gate). *(Caveat: `tfsec` has folded into Trivy — prefer checkov/conftest for the Terraform lane, or verify Trivy before citing tfsec.)*
