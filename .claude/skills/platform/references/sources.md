# Sources — the platform canon

The external best-practice this skill cites. **Cite-and-link**; never reproduce reserved text. Verified against the primary source during authoring.

These are the **generic floor**. The Sei profile (`sei-platform-profile.md`) is what *actually applies*. It **overrides** some of these as the fleet *default* (Pod-Identity over IRSA, SOPS over CSI); each entry below flags its override. An override sets the default, not an absolute. The profile documents the narrow exceptions where the generic pattern is still in use. Those are IRSA for old-SDK workloads, and a workload reading Secrets Manager at runtime.

- **§opengitops — GitOps principles.** Declarative; versioned + immutable in git; pulled automatically by agents; continuously reconciled (drift-corrected). The four OpenGitOps v1.0 principles (CNCF). — https://opengitops.dev/ (Apache-2.0). Implementation (Flux/Argo) is a secondary reinforcer.

- **§kustomize — base/overlay model.** "A *base* is a kustomization referred to by some other kustomization". "An *overlay* is a kustomization that depends on another". A *variant* = an overlay applied to a base. — https://kubectl.docs.kubernetes.io/references/kustomize/glossary/ + https://kubernetes.io/docs/tasks/manage-kubernetes-objects/kustomization/ (CC-BY-4.0). (This fleet uses the two-layer `clusters/base`+`manifests/base` form with `patches`/`components`/`replacements`, **not** `postBuild.substitute` — profile §2.)

- **§irsa — IAM Roles for Service Accounts (the generic the profile OVERRIDES).** An SA binds to an IAM role. The pod gets a projected OIDC token exchanged via STS `AssumeRoleWithWebIdentity`. Least-privilege per-SA. "You can scope IAM permissions to a service account, and only Pods that use that service account have access." — https://docs.aws.amazon.com/eks/latest/userguide/iam-roles-for-service-accounts.html (AWS docs).

  **Override:** the Sei fleet *defaults* to **EKS Pod Identity** (the `eks-pod-identity-agent` + per-(cluster,ns,SA) associations) — profile §3, `kit-cloud-auth-pod-identity`. IRSA is the broadly-applicable pattern + the cited mechanism. Here the profile **retains it as the documented escape hatch**, not banned. It covers old-SDK workloads that cannot consume the Pod-Identity endpoint (prod `pacific-1` CronJobs).

- **§pod-security — Pod Security Standards + Admission.** Three cumulative levels — Privileged → Baseline → Restricted ("Heavily restricted policy, following current Pod hardening best practices"). The built-in admission controller for Pod Security enforces a level per-namespace via labels. — https://kubernetes.io/docs/concepts/security/pod-security-standards/ + .../pod-security-admission/ (CC-BY-4.0). (The fleet pins `restricted` at the cluster minor + adds a CEL ValidatingAdmissionPolicy for what PSS misses — profile §5.)

- **§secrets — Secrets Store CSI Driver + SecretProviderClass (the generic the profile OVERRIDES).** Mount external-store secrets into the pod filesystem via a namespaced `SecretProviderClass`, instead of relying on plain k8s Secrets. — https://secrets-store-csi-driver.sigs.k8s.io/ + https://github.com/aws/secrets-store-csi-driver-provider-aws (Apache-2.0 / AWS).

  **Override:** the Sei fleet *delivers* k8s Secrets via **SOPS-in-git + per-cell KMS** (no CSI/SecretProviderClass, no ESO, no Sealed Secrets) — profile §4, `kit-secrets-sops-kms`. This overrides the *delivery* path only. A workload may still read a secret from AWS Secrets Manager at runtime via its own role (`heatseeker`), so SM is not fleet-absent. What's absent is SM/CSI as the k8s-Secret delivery mechanism. *(Caveat: the "plain k8s Secrets are only base64-encoded at rest by default" rationale is widely repeated and the k8s docs index corroborates it. Research did not re-quote it from the encryption-at-rest page. Treat it as corroborated-not-primary; verify that page before citing it as a load-bearing fact.)*

- **§nsa-cisa — Kubernetes Hardening Guide.** Run containers non-root. Read-only root filesystem ("Use read-only root file systems where possible"). Minimal base images ("Use minimal base images to reduce attack surface"). RBAC least-privilege. NSA/CISA Kubernetes Hardening Guidance v1.2 (Aug 2022) — **US Government work, public domain** (most citation-friendly of the set).

  **Cite the k8s.io blog summary as the verified source** — https://kubernetes.io/blog/2021/10/05/nsa-cisa-kubernetes-hardening-guidance/ (CC-BY-4.0); the canonical PDF is https://media.defense.gov/2022/Aug/29/2003066362/-1/-1/0/CTR_KUBERNETES_HARDENING_GUIDANCE_1.2_20220829.PDF. *(Caveat: the .mil PDF 403'd the research fetcher, so its page/section numbers have no verification. Do **not** pin a specific page or section. Cite the substance via the k8s.io blog, and quote the PDF directly only after you have opened it.)*
