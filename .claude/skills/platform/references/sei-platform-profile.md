## The fleet in one paragraph

A **multi-cell EKS + Flux-CD GitOps fleet** at K8s 1.34, single AWS account `189176372795`. Cells: `prod` (eu-central-1 hub — Grafana + Thanos query, **VPC-CNI**), `prod-euw1`, `prod-use2` (producer cells — **Cilium**, `grafana.enabled:false`, federate up), `harbor` (multi-tenant dev/staging), `dev`. Secrets are **SOPS-in-git** (the in-cluster delivery mechanism); cloud-auth is **EKS Pod Identity** (the default). The companion repo **`sei-infra`** is a *separate, legacy EC2-based* fleet (terraform + `user_data` + SSH keys) — **read-mostly**; the EKS fleet is the migration target. The current `platform-engineer` agent's expertise **over-generalizes** — some of it (LLM/Anthropic API, EIP-712 KMS *signing*) is genuinely absent here, but the rest (IRSA, AWS Secrets Manager, Python images, GitHub-App auth) exists in **narrow, documented exceptions** and must not be treated as the fleet default — nor as fleet-absent. See the corrections below.

## Hard conventions (these override generic habit)

1. **GitOps via Flux v2 — the reconcile spine.** A `GitRepository(main)` → a root `Kustomization` per `clusters/<cell>`, with `prune: true`, `interval: 10m`, and `decryption: { provider: sops }`. **There is no `spec.dependsOn` between Kustomization CRDs** — ordering is (a) resource order within a `kustomization.yaml`, then (b) HelmRelease-level `dependsOn` (e.g. karpenter `dependsOn` cilium). *Cited:* `clusters/prod/flux-system/gotk-sync.yaml`, `clusters/base/cni-cilium/kustomization.yaml`.

2. **Two-layer Kustomize composition (plain Kustomize, not classic overlays).** `clusters/base/<infra-component>` (cluster services) vs `manifests/base/<workload>` (seid/waterway/monitoring/genesis). A cell dir overlays via `resources: [../../base/X]` + **`patches:`** + **`components:`**, and per-cell variance is `configMapGenerator` + **`replacements`** — **never `postBuild.substitute`** (zero repo use). *Cited:* `clusters/prod/cert-manager/kustomization.yaml`, `clusters/base/cni-cilium/`.

3. **Cloud-auth defaults to EKS Pod Identity — IRSA is the documented escape hatch, not absent.** The `eks-pod-identity-agent` addon on every cluster; per-workload `terraform-aws-modules/eks-pod-identity/aws` associations scoped to (cluster, namespace, ServiceAccount). S3 access is scoped by session tag (`aws:PrincipalTag/kubernetes-namespace`). **Default to Pod Identity** — but a `role-arn` SA annotation is **not automatically wrong**: the prod cell's `pacific-1` (mainnet) runs two CronJobs (`state-size-analyzer`, `archive-volume-snapshot`) on **IRSA on purpose** — `seidb` bundles an `aws-sdk-go` too old to consume the Pod-Identity credential endpoint (`169.254.170.23`), so it falls through to "no providers in chain"; IRSA's `AssumeRoleWithWebIdentity` works on old SDKs. **Confirm the rationale (the TF carries the comment) before flagging a `role-arn` annotation** — a justified old-SDK IRSA usage is *correct*, not a defect to rewrite. *Cited:* `terraform/aws/189176372795/eu-west-1/prod-euw1/*.tf` (Pod-Identity associations), `terraform/aws/189176372795/eu-central-1/prod/state-size-analyzer.tf:1-9` (the IRSA exception + its rationale), `clusters/prod/pacific-1/{state-size-analyzer,archive-volume-snapshot}-cron.yaml` (the `role-arn` annotations), `cell-bootstrap.md` Appendix A. **(Generic best-practice says IRSA; this fleet's *default* is Pod Identity — `sources.md` §IRSA is the generic floor — with IRSA retained for the old-SDK exception above.)**

4. **Secrets are *delivered* into the cluster via SOPS-in-git + per-cell KMS — NOT a CSI SecretProviderClass / ESO / Sealed Secrets.** One KMS CMK + alias per cell (`alias/<cell>`); each `clusters/<cell>/.sops.yaml` has ONE `creation_rules` entry (`path_regex: .*`, `encrypted_regex: ^(data|stringData|.+=)$`) → that cell's KMS ARN; Flux's kustomize-controller decrypts. **Encrypt from *inside* the cell dir** (the `.sops.yaml` is CWD-resolved — encrypting elsewhere picks the wrong key). SOPS-wrapped validator signing keys + pagerduty keys live in-tree. **No External Secrets Operator, no Sealed Secrets, no Secrets Store CSI / SecretProviderClass.** Distinguish *delivery* from *a workload reading a cloud secret at runtime*: the `heatseeker` workload **does** read from AWS Secrets Manager via its own Pod-Identity role (`secretsmanager:GetSecretValue` on `pacific-1/heatseeker-*`) — so "no Secrets Manager" is **wrong** as a blanket claim; what's absent is SM-as-the-k8s-Secret-delivery-path. *Cited:* `clusters/prod/.sops.yaml`, `terraform/aws/189176372795/eu-central-1/prod/heatseeker.tf:31-35` (the SM grant), `cell-bootstrap.md` Appendix B. **(Generic best-practice says CSI/SecretProviderClass; this fleet overrides it for k8s-Secret delivery — `sources.md` §secrets is the generic floor.)**

5. **Pod Security = PSS `restricted`, version-pinned, + a CEL ValidatingAdmissionPolicy.** Namespaces pin `enforce/audit/warn: restricted` at the cluster minor (`v1.34`); a `ValidatingAdmissionPolicy` (in-tree GA, CEL) adds what PSS misses — bars ephemeral containers + enforces a container-name allowlist (the `kubectl debug` / sidecar-injection netns vector). **NetworkPolicy is enforced only on Cilium cells** — on the VPC-CNI hub a NetworkPolicy *object* may exist (e.g. `clusters/prod/monitoring/grafana-operator.yaml`) but the `vpc-cni` addon runs without `ENABLE_NETWORK_POLICY`, so it is documentation-grade (an NP file present ≠ enforced); PSS + VAP is the real lock. The VAP details (the CEL contract, the fail-closed-by-logic-not-error subtlety, the label-coupling fragility) are in `references/kit-pod-security-vap.md`. *Cited:* `clusters/prod/walle/namespace.yaml`, `walle/podcomposition-policy.yaml`, `eu-central-1/prod/eks.tf` (vpc-cni, no `ENABLE_NETWORK_POLICY`).

6. **CNI is split: Cilium (producer/harbor) vs VPC-CNI (prod hub).** Cilium cells use kubeProxyReplacement, cluster-pool IPAM (`100.64.0.0/14`), VXLAN UDP/8472, and a **hand-allocated `cluster.id`** per cell (registry in `cell-bootstrap.md` Phase 0). The Cilium overlay creates the **cilium#30111** apiserver→pod-CIDR *dial* failure — metrics-server / istiod need `hostNetwork` (this is the hostNetwork fix; it is **not** the NLB rule below). **NLB `target-type` tracks the CNI, not a fleet-wide value:** VPC-CNI cells use `ip` (pod ENIs are VPC-addressable, so the NLB targets pods directly), Cilium cells use `instance` (cluster-pool pod IPs aren't VPC-routable for the NLB). *Cited:* `clusters/base/cni-cilium/cilium.yaml` (+ the cni-cilium component's `defaultTargetType: instance`), `clusters/base/kube-system/metrics-server.yaml` (cilium#30111 hostNetwork), `clusters/prod/arctic-1/networking/p2p/*.yaml` (`ip`) vs `clusters/prod-euw1/arctic-1/networking/p2p/*.yaml` (`instance`), `.agent/runbooks/cilium.md`.

7. **sei-k8s-controller is deployed here, staged via `?ref=` pinning.** `clusters/base/sei-k8s-controller/` references the controller repo at one `?ref=<sha>`; a prod cell pins a **newer** sha for staged rollout; config via `manager-patch.yaml` env + a `controller-config.yaml` ConfigMap. **This skill owns that manifest/patch/config; `/kubernetes` owns the controller *code*.** *Cited:* `clusters/base/sei-k8s-controller/` vs `clusters/prod/sei-k8s-controller/`.

8. **Container runtime: static-musl `seid`.** `containers/seid-musl/` is a multi-stage Alpine **static musl** link of `seid`/`price-feeder`/`seictl` (pulling `libwasmvm*_muslc.a`); `containers/genesis/` pre-bakes multi-node genesis at build; `containers/actions-runner/` is the in-cluster self-hosted GHA runner. Images → ECR `189176372795.dkr.ecr.us-east-2.amazonaws.com/sei/*`. `waterway` is the EVM JSON-RPC/WS reverse proxy. *Cited:* `containers/*/Dockerfile`, `manifests/base/{seid,waterway}/`.

## The agent boundary (confirmed from the repos)

- **platform-engineer** (this skill): HelmRelease plumbing + `valuesFrom`/version-pin, Kustomize structure, Pod-Identity/IRSA→PodIdentity wiring, SOPS/KMS, the controller-deploy manifests, terraform cell provisioning, container builds.
- **observability-platform-engineer**: the telemetry-stack *values' contents* + PromQL/LogQL (you own the HelmRelease shell + `valuesFrom`, they own what's inside).
- **k8s-capacity-management**: NodePool sizing, requests/limits, scheduling.
- **kubernetes-specialist** (`/kubernetes`): the sei-k8s-controller *code* + CRDs (you deploy it; they author it).
- **network-specialist**: NetworkPolicy/CiliumNetworkPolicy intent + the Cilium datapath design (you own the CNI bring-up + hostNetwork/NLB plumbing). **sei-network-specialist**: Sei node P2P/RPC.
- **sre-engineer**: SLOs/alerts/runbooks/incidents on the running system.

## Stale-agent corrections (don't over-generalize the old persona)

The old persona's bullets split two ways. **Don't conflate "the persona over-emphasized X" with "X is fleet-absent"** — four of the six are present, just narrowly scoped, and treating a present-but-narrow pattern as absent would tell the agent to "rewrite" correct fleet code.

- **Genuinely absent — do not carry:** LLM/Anthropic API integration; EIP-712 KMS *transaction signing* (KMS here = SOPS decryption + EKS secrets-at-rest, not signing).
- **Present but narrowly scoped — Pod-Identity/SOPS/static-Go are the *defaults*, these are the documented exceptions; don't over-generalize in either direction:**
  - **IRSA** — the fleet *default* is Pod Identity, but IRSA is the documented old-SDK escape hatch in prod `pacific-1` (§3). Don't flag a justified `role-arn` annotation as wrong.
  - **AWS Secrets Manager** — not the k8s-Secret delivery path (that's SOPS), but the `heatseeker` workload reads from SM at runtime via its Pod-Identity role (§4). Don't claim SM is fleet-absent.
  - **Python container images** — the *seid/chain* runtimes are static-musl Go, but `heatseeker` is a `python:3.11-slim` image deployed in the prod cell (`clusters/prod/heatseeker/`, `sei-infra/monitoring/heatseeker/Dockerfile`), plus `~/sei-infra/tools/*.py`. Don't claim Python is fleet-absent.
  - **GitHub-App auth** — *Flux git* auth is SSH deploy keys (`gotk-sync.yaml`), but the in-cluster GHA runner authenticates to GitHub via a **GitHub App** (`clusters/dev/gha-runner/github-app-auth.yaml` → `uci-default.yaml`). Don't claim App auth is fleet-absent.
- **CSI SecretProviderClass / ESO / Sealed Secrets** — genuinely absent (SOPS-in-git is the delivery path); this one *is* a clean "not used here."
