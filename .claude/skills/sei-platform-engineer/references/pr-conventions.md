# PR conventions for onboarding

Used by `seictl onboard` when generating engineer onboarding PRs against `sei-protocol/platform`.

## Branch naming

| Purpose | Pattern | Example |
|---|---|---|
| Onboarding | `<alias>/onboard-<alias>` | `bdchatham/onboard-bdchatham` |
| Engineer's later workload PRs (rare) | `<alias>/<short-description>` | `bdchatham/seinode-pacific-1-archive` |

Most workloads are direct-applied via `seictl bench up`, not via PRs. PRs land only for resources that should live in GitOps (long-lived RBAC additions, namespace edits, quota tweaks).

## PR title

`onboard <alias>: set up engineer namespace on harbor`

## PR body template

```markdown
## Onboarding: <alias> on harbor

**Engineer:** <name> <<email>>
**Alias:** <alias>
**Namespace:** eng-<alias>

### What this PR does

Creates `clusters/harbor/engineers/<alias>/`:

- `kustomization.yaml`
- `namespace.yaml` — `eng-<alias>` with cells-forward labels (see `references/interim-namespace-strategy.md`)
- `bench-seiload-sa.yaml` — `ServiceAccount` for benchmark workloads (Pod Identity wired by Terraform, see below)

### Terraform diff (apply alongside this PR)

```hcl
[generated TF block for Pod Identity association — see references/interim-namespace-strategy.md]
```

Reviewer: please apply the Terraform diff before merging this PR. Without it, `seictl bench up` will fail with `permission denied` on S3 writes.

### After merge

1. Flux reconciles in ~60s
2. Engineer can verify with `seictl context` (should show `eng-<alias>` accessible)
3. Engineer can `seictl bench up --image <ref>` immediately

### Generated by

seictl `<version>` via `seictl onboard --alias <alias>`
```

## Reviewer conventions

[outline]

- Reviewers: platform team (auto-assigned via CODEOWNERS once configured)
- SLA: same-day for onboarding PRs (engineer is blocked until merge)
- What reviewers check:
  - Alias matches an active platform engineer
  - Cells-forward labels correct
  - Terraform diff matches the existing pattern (no IAM scope expansion vs `harbor-autobake-seiload`)
  - No additional resources beyond what `seictl onboard` is meant to generate (no manual additions slipped in)

## Conventional commits

Onboarding commit message: `feat(harbor): onboard <alias>`

Subsequent engineer workload commits: `feat(harbor/<alias>): <description>` (when the rare workload PR is needed)
